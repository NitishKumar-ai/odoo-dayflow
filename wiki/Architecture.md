# Architecture

Dayflow is one Next.js 16 App Router app and one Postgres database. A browser
request either renders a server component (read) or posts a server action
(write). Both talk to Drizzle on the same Node process.

```
Browser
  │  GET page  /  POST server action
  ▼
Next.js (src/app, src/actions)
  │  requireUser() or requireAdmin()
  ▼
src/lib/*  (rules + queries)
  ▼
Drizzle  →  PostgreSQL
```

## Why there is no `/api` folder

Mutations are `"use server"` functions imported by forms via `useActionState`.
That keeps the write path next to the Zod schema and the authorisation check.
Adding a REST handler would duplicate those checks.

## Two route groups

| Group | Layout | Who sees it |
|---|---|---|
| `(auth)` | Centered card, brand | Signed-out visitors (`/signin`, `/signup`) |
| `(app)` | Header, nav, sign-out | Anyone with a valid session |

`/` is `force-dynamic`. It reads the session cookie and redirects to
`/dashboard` or `/signin`. `verify-email` sits outside both groups so a
signed-out person can activate an account.

Admin screens live under `(app)/admin/*`. They call `requireAdmin()`, which
sends employees back to `/dashboard`. Admins also keep the employee nav
("My own records") so they can clock in as themselves.

## Authorisation is per-action

There is no middleware that locks routes. `requireUser()` and `requireAdmin()`
in `src/lib/auth.ts` run:

- at the top of every signed-in page
- inside every mutation that touches data

A guessed URL never grants a write. A missing `require*` on a new action
makes that action public — that is the main foot-gun in this codebase.

Sign-up, sign-in, verify, and sign-out are the only public actions.

## Data flow on a typical write

1. Client form posts to a server action.
2. Action parses `FormData` with Zod.
3. Action re-checks the session.
4. Action queries or mutates through `db` from `src/db/index.ts`.
5. Action calls `revalidatePath()` for every page that shows the changed rows,
   including the other role's view (approving leave refreshes `/leave` and
   `/admin/leave`).
6. Action returns `{ error?: string; ok?: string }`.

## Database access

`src/db/index.ts` opens a `postgres.js` pool (`max: 5`) and caches it on
`globalThis` in development so hot reload does not leak connections. Schema
lives in `src/db/schema.ts`. Migrations live in `drizzle/`.

Numeric columns come back as strings. Coerce through `src/lib/money.ts`.

Dates in the product are local `YYYY-MM-DD` strings. `new Date("2026-08-22")`
parses as UTC and can shift the day — use `src/lib/dates.ts`.

## Next.js 16 specifics

- `params` and `searchParams` are promises; await them.
- `cookies()` is async.
- Route props are globally typed (`PageProps<"/admin/employees/[employeeId]">`)
  after a `dev` or `build` has written `.next/types/`.
- Read `node_modules/next/dist/docs/` before changing routing or caching.
  `AGENTS.md` is regenerated by `next dev`; commit it rather than deleting it.
